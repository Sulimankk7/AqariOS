# AqariOS test API inventory

Source snapshot: 2026-09-08. This inventory was rebuilt from `src/PropertyOS.Api`, application commands/validators/handlers, domain enums, and the web/mobile clients. It intentionally covers realistic product journeys rather than development-only and platform-administration endpoints. Runtime OpenAPI should be checked at `/swagger/v1/swagger.json` after every API change.

## Cross-cutting contract

- All routes below use API version `v1`. Unless marked anonymous, they require a Bearer JWT and a company/tenant context. Company data is tenant-isolated in handlers and persistence.
- Validation failures are `400` for MVC binding/data annotations or `422` for FluentValidation/business validation, depending on the action pipeline. Authentication is `401`, missing permission is `403`, missing tenant-owned entity is `404`, uniqueness/state collision is `409`, and a business transition rejection is generally `422`. Errors use `ProblemDetails`/`ValidationProblemDetails`.
- The global fixed-window limiter is keyed by trusted remote IP: 100 requests/60 seconds by default, no queue, with `429 application/problem+json` and `Retry-After`. Named policies are layered on top: login/tenant activation 5/minute; OTP request 3/minute; OTP verify 10/minute; password-reset request 3/minute; password-reset verify/complete 10/minute; contact request 3/minute; marketplace viewing request 5/minute.
- List responses are JSON arrays unless a row says keyset page. IDs returned by create actions are JSON GUID scalars. `204` actions have no body. Dates are ISO `DateOnly` (`YYYY-MM-DD`) or ISO UTC timestamps as identified by request DTOs.
- Test labels: **S** smoke, **L** normal read-only load, **M** bounded mixed writes, **T** stress, **P** spike, **O** soak. Destructive lifecycle actions are functional-only and never part of unattended load.

## File upload dependency used by seeding

The signed lease flow is `POST /api/v1/files/upload-request` (`moduleName`, entity ID, filename, MIME, size) -> capability-protected raw `PUT uploadUrl` -> `POST /api/v1/files/confirm` (`fileId`, storage key, original filename, MIME, size) -> attach document. Upload request and confirm return `200`; raw physical upload returns `204`. File validation checks size, extension/MIME, magic bytes, sanitized names, and company ownership. The module name is a validated non-empty storage-key segment, not a published enum.

## Scenario selection rationale

- Smoke performs eight deterministic contract reads spanning public, owner, lease/payment, and tenant contexts.
- Load, stress, spike, and soak are read-only with a 70% owner / 25% tenant / 5% public mix. They use only IDs and tokens emitted by the seeder.
- Mixed is a bounded shared-iterations test (20 writes by default): each iteration performs an owner read plus one valid maintenance create. The title contains the run/VU/iteration identity. This makes accumulation explicit and capped.
- Authentication issuance, activation, file upload, lease lifecycle, payment approval, deletion/archive, OTP/reset, viewing-request creation, and external utility synchronization remain functional-only because repetition is security-limited, stateful, destructive, or externally coupled.
